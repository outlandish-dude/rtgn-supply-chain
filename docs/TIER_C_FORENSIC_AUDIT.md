## 2. Issue 1: Checkpoint Architecture & Tensor Count Consistency

### A. Confirmed Facts
1. The checkpoint file `experiments/rtgn_tier_c/checkpoints/best_rtgn_model.pt` contains a `model_state_dict` dictionary with exactly **90 keys**.
2. Instantiating `RTGNModel` with `num_packages=1933`, `in_feature_dim=13`, `hidden_dim=64`, `time_dim=32`, `heads=4`, `dropout=0.2`:
   - Number of learnable parameters (`len(list(model.parameters()))`): **87 tensors** ($129,345$ parameters).
   - Number of registered buffers (`len(list(model.buffers()))`): **3 tensors**.
   - Length of model `state_dict` (`len(model.state_dict())`): **90 tensors**.
3. The 3 persistent buffers registered in `RTGNModel` are:
   - `time_encoder.frequencies`: Shape `[16]`, `torch.float32` (Harmonic basis frequencies)
   - `package_memory.memory`: Shape `[1933, 64]`, `torch.float32` (Dynamic GRU memory states)
   - `package_memory.update_count`: Shape `[1933]`, `torch.int64` (Per-package event counts)
4. Calling `model.load_state_dict(checkpoint["model_state_dict"], strict=True)`:
   - Missing keys: `0`
   - Unexpected keys: `0`
   - Shape mismatches: `0`

### B. Identified Inconsistency & Root Cause
- **Inconsistency:** `scripts/verify_rtgn_checkpoint.py` printed `[+] State-dict validation: PERFECT STRICT MATCH (All 87 parameter tensors loaded)`, whereas `scripts/demo_rtgn.py` printed `* State-Dict Match : 90 tensors loaded strictly (0 missing, 0 unexpected)`.
- **Confirmed Root Cause:**
  - In `scripts/verify_rtgn_checkpoint.py` line 214, the log output was hardcoded with the text:
    `"(All 87 parameter tensors loaded)"`, referencing `len(list(model.parameters()))`.
  - In `scripts/demo_rtgn.py` line 302, the print statement used `{len(model.state_dict())}`, which evaluates to 90 ($87 \text{ parameters} + 3 \text{ buffers}$).
  - Both scripts load the identical checkpoint file without any missing or unexpected weights.
